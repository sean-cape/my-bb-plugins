# 02 — Directives, stop, retry, resume and steer in the loop's core

**What to build:** The server side of every intervention, reachable through RPCs and a `bb kanban loop` CLI command, with no UI yet. Loop state gains one optional pending directive (hand off at ready, hand off after the running step, skip the next review), the time the current phase began, and two Needs-you reasons: "handed off" and "stopped". Reducer events set, replace and clear the directive; the reducer consumes it: hand off at ready records the commit and evidence at the next ready, spawns nothing and goes to Needs you as handed off with no attention level; hand off after step keeps the next checks result or completed review (its findings listed as open) and goes to Needs you as handed off, a failing check going to Needs you as checks instead of back to the thread, and while classifying it waits for the review to complete; skip review once runs the checks at the next ready and on a pass goes to Needs you as handed off, on a failure bounces to the thread and keeps the directive. A directive clears when consumed, on undo, on rethink and on loop off. Stop now, allowed while checking, classifying or reviewing, issues the existing stop-superseded action, discards the step and goes to Needs you as stopped. Retry, allowed at a loop error, clears the reason, resets the automatic retries, counts a manual retry and re-spawns the failed step at the same commit. Resume with a message, allowed at Needs you, returns to building as a round of the user's and prompts the thread with their words under the steering wrapper plus the builder contract. Steer is an adapter, not a reducer event: it sends the user's text to the card's thread wrapped as "the user says, from the board: …; this is steering, not a new task; carry on and when the work is done commit, run the checks and report ready as before", allowed whenever the card has a thread and the loop is not accepted or landed. The dispatch wrapper stamps the phase-start time when an event changes the phase, so the reducer stays clock-free. A shared function maps every reason to a bucket (approve, review, stuck) and a detail word, with handed off and stopped in the review bucket as "not reviewed" and "stopped". Hand-offs and stops notify and mark unread through the existing stop path. The brief and the chip may still show the new reasons crudely; the strip ticket makes them read well.

**Blocked by:** None — can start immediately.
